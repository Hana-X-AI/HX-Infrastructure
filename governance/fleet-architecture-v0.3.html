Tech-Stack Alignment — Hana-X on the Real Fleet

Candidate v0.3 folds the research/validation corrections into the frozen v0.1 baseline. No workload moved hosts — every server keeps its v0.1 role. What changed from v0.1 — configuration and sequencing only; the fleet layout is unchanged.

  • LiteLLM → PostgreSQL. The gateway on hxs-8 is backed by a dedicated litellm database on the hxs-9 Postgres. SQLite is not supported and was blocking.
  • Embeddings/reranker via TEI or Infinity on hxs-4's 8 GB card — lighter and purpose-built — not vLLM.
  • LightRAG is the canonical name (“LiteRAG” dropped). A first-ingest freeze gate is now required before any bulk ingest.
  • Mem0 boundaries. Own Qdrant collection (distinct from RAG), SQLite history, and no dependence on Mem0 graph memory (graph lives in LightRAG).
  • Service isolation standard. One virtualenv per service even when co-located — LangGraph and Mem0 stay in separate venvs on hxs-11.
  • Observability is external to the 15-server map (separate spare box); each host still gets local exporters in Phase 1.
  • MCP security hardening deferred to a post-platform workstream — logged, not a bring-up prerequisite.
  • Settled: hxs-3 gpt-oss runs on both cards at TP=2 (closed). Benchmark-gated: Coder-32B staying on hxs-2 (PCIe-3) — validate, don't remap on paper.

GPU serving tier — the four GPU hosts

hxs-1, hxs-2 and hxs-3 each pool a matched card pair via tensor-parallelism into one ~32 GB unit. hxs-4's pair is mismatched, so its cards run as independent slots. No TP group mixes GPU generations. hxs-3 and hxs-4 also host data services (LightRAG, Qdrant) on their CPU/RAM/NVMe. Build-time pin for the Blackwell (RTX 50-series) hosts: vLLM 0.11.x / PyTorch cu128 / CUDA 12.8 / driver ≥575, FlashAttention-2 (FA3 unsupported on Blackwell).

Notes & open items

LiteLLM datastore corrected

LiteLLM is Postgres-only; the gateway on hxs-8 uses a dedicated litellm database on the hxs-9 Postgres. Issue separate virtual keys per client (Open WebUI, LangGraph) for cost attribution.

First-ingest freeze gate

Before any bulk ingest, freeze and round-trip-validate: embedding model, embedding dimension, LightRAG storage backend, and the Qdrant collection design. These are immutable after first ingest; a dimension mismatch corrupts the store.

hxs-3 GPU topology — closed

gpt-oss-20b runs on both RTX 5060 Ti cards at TP=2. The single-card option (its ~13 GB MXFP4 weights fit one card) is recorded but not adopted. Settled.

Coder-32B placement — benchmark-gated

hxs-2 is the PCIe-3 host; TP=2 all-reduce is bottlenecked there. Do not remap on paper. In Phase 3, benchmark decode throughput / latency at target context; only consider hxs-1 if it falls below an acceptable bar and reasoning tolerates the swap.

Embeddings / rerank runtime

Serve BGE-M3 / Nomic / bge-reranker-v2-m3 with TEI or Infinity (dynamic batching, low VRAM) on hxs-4's 8 GB card, not vLLM. Route through LiteLLM (/embeddings, Cohere-shaped /v1/rerank).

Mem0 boundaries

Mem0 uses its own Qdrant collection (distinct from RAG), keeps history in SQLite on a durable path, and does not use graph memory (removed from OSS). Graph intelligence stays in LightRAG on hxs-3.

Service isolation standard

One virtualenv per service, even co-located: LangGraph and Mem0 stay in separate venvs on hxs-11, each pinned to compatible LangChain-family versions. systemd per unit; absolute venv interpreter in ExecStart.

Observability is external

Metrics/logs/backups run on a separate spare box outside the 15-server map — not a gap in the fleet role map. Each host installs local exporters in Phase 1 (node_exporter; dcgm-exporter on GPU hosts).

MCP security — deferred

Auth, reverse-proxy policy, Origin allow-listing, and mTLS/bearer standards for networked MCP servers are a post-platform hardening workstream, kept in the backlog. Meanwhile bind servers to the LAN interface (not 0.0.0.0) and standardize on Streamable HTTP.

Qwen 3.8 27B is unreleased

The hxs-1 slot is sized for a 27B dense model at 4-bit. Confirm quant & VRAM at launch before committing the host.

Still open / build-time

Exact context windows and quantization/runtime flags per model; final embedding model + dimension; exact MCP server implementations/versions where maturity varies (Crawl4AI, Mem0 MCP). Resolve during the relevant roadmap phase.

Roadmap sequence (for the next artifact)

With v0.3 frozen, the phased build follows: 1 Fleet foundation (OS, users, storage, DNS, systemd, Python/NVIDIA baseline, per-host exporters) · 2 Shared state & edge (Postgres + Redis, NGINX, LiteLLM) · 3 GPU inference (bring-up + benchmark; resolve the coder-32B question) · 4 Retrieval & ingestion (Qdrant, TEI/Infinity, LightRAG, Docling, Crawl4AI — with the first-ingest gate) · 5 Agents & MCP (LangGraph, Mem0, FastMCP, MCP servers) · 6 Applications (Open WebUI, CopilotKit / AG-UI) · 7 Dev / test / demo workflows · 8 Hardening (observability integration, backups, recovery, and the deferred MCP security workstream).
