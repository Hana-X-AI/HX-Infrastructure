On the FQDN column. These names resolve through dnsmasq on the router, loaded from /jffs/hx-hosts. No domain suffix is set on the servers themselves, so hostname -f returns the short name on every host. Automatic loading of the records after a router reboot is unproven — see act-011.

The control plane resolves. hxs-cp.hx.local.arpa was verified forward and reverse against 192.168.50.1 on 2026-08-13, both returning 192.168.50.215. Its name uses a role suffix rather than the numeric hxs-N pattern published for the fleet, which is a deliberate distinction between the control plane and the servers it operates.

What the table shows

The control plane has no wired network

wlp0s20f3 is the only interface on hxs-cp — there is no Ethernet port present, not merely one left unplugged. Every SSH path to all fifteen fleet servers runs over a single Wi-Fi link.

The control plane is a laptop

An HP Elite x360 1040 G9 convertible. Its memory is soldered at 15.8 GB and cannot be expanded, and suspend-on-lid behaviour has not been checked — both matter for a host expected to stay reachable.

Compute is concentrated on four hosts

All 8 discrete GPUs and all 122,458 MiB of VRAM sit on hxs-1 through hxs-4. The other eleven have integrated graphics only, suitable for console output rather than compute.

So is storage

Of roughly 29 TB installed, about 26 TB is on those same four hosts, most of it unallocated. The eleven small form factor hosts carry one device each that is also the boot disk.

No expansion path on eleven hosts

Every small form factor host is a 35 W or 65 W desktop-mini chassis: no spare drive, no free bay, no PCIe slot. Two free DIMM slots on hxs-7 and hxs-8 are the only physical upgrade available in that group.

VRAM figures are measured

Each is reported by nvidia-smi after the approved driver install, and agrees with the value the kernel reported before any vendor driver was present.

hxs-4 GPUs are mismatched

16311 MiB and 8151 MiB in the same host. Any work assuming matched devices is constrained by the smaller card.

hxs-15 cannot host a hypervisor

VT-x is not exposed to the operating system — the only host in fifteen. The silicon supports it, so the cause is firmware. Tracked as iss-011.

hxs-13 is not a drop-in equivalent

It shares a model name with five other hosts but runs a Skylake CPU, older graphics, slower memory and a SATA boot device rather than NVMe.

No ECC, no out-of-band management

Memory is non-ECC on every server, and no host has a baseboard management controller, so there is no out-of-band recovery path anywhere in the fleet.
