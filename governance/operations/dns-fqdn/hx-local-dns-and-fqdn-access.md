# HX local DNS and FQDN access

## purpose

Provide a simple, persistent source of truth for local server DNS on the HX network so every server can be reached by its FQDN.

## network DNS

- Router: `HX-Router`
- Router IP / DNS resolver: `192.168.50.1`
- Local domain: `hx.local.arpa`
- Resolver: router `dnsmasq`
- Primary LAN DHCP remains disabled.
- Clients must use `192.168.50.1` as DNS for these names to resolve.

## persistent DNS files on HX-Router

Persistent source of truth:

```text
/jffs/hx-hosts
```

Loader:

```text
/jffs/hx-dns-load.sh
```

Runtime destination:

```text
/etc/hosts
```

`/etc/hosts` is regenerated by stock ASUSWRT, so it is not the persistent source.

The loader replaces the explicit HX-managed block in `/etc/hosts` with the contents of `/jffs/hx-hosts`, then reloads `dnsmasq`. This is a full replacement of the managed block, not an additive merge: existing HX records that have changed are updated, stale records are removed, and only the new `/jffs/hx-hosts` content survives. Records outside the managed block are left untouched.

Run the loader with:

```sh
/jffs/hx-dns-load.sh
```

## naming convention

Server DNS names must match the server hostname and project registry.

Fleet workload servers use a numeric suffix:

```text
hxs-N.hx.local.arpa
```

Examples:

```text
hxs-1.hx.local.arpa
hxs-10.hx.local.arpa
hxs-15.hx.local.arpa
```

Infrastructure hosts that are not fleet workload servers use a short role suffix instead of a number:

```text
hxs-cp.hx.local.arpa
```

`cp` is the control plane. A role suffix marks a host as outside the numbered fleet, so the name itself says the machine is not a workload server.

Do not use `hx-N`.

## verification

Test one server:

```sh
nslookup hxs-1.hx.local.arpa 192.168.50.1
```

Test the full fleet:

```sh
for n in $(seq 1 15); do
  echo "=== hxs-$n ==="
  nslookup "hxs-$n.hx.local.arpa" 192.168.50.1
done
```

All `hxs-1` through `hxs-15` have been verified resolving through `192.168.50.1`.

## SSH by FQDN

Once DNS resolves, servers can be addressed by FQDN instead of IP:

```sh
ssh hxsa@hxs-1.hx.local.arpa
ssh hxsa@hxs-11.hx.local.arpa
ssh hxsa@hxs-15.hx.local.arpa
```

DNS resolution only maps the name to the IP. The target service, such as SSH on TCP/22, must still be available on that server.

## adding or changing a server record

Edit `/jffs/hx-hosts`, then run:

```sh
/jffs/hx-dns-load.sh
```

Verify:

```sh
nslookup <server-name>.hx.local.arpa 192.168.50.1
```

Example:

```sh
echo '192.168.50.216 hxs-16.hx.local.arpa hxs-16' >> /jffs/hx-hosts
/jffs/hx-dns-load.sh
nslookup hxs-16.hx.local.arpa 192.168.50.1
```

Avoid duplicate or stale records for the same IP or hostname.

Check the record list above before choosing an address. `192.168.50.200` through `192.168.50.215` are allocated; the first free address is `192.168.50.216`.

## router reboot behavior

The DNS records in `/jffs/hx-hosts` persist across router reboot.

Automatic execution of the loader after reboot has not been proven on this stock ASUSWRT firmware.

After any router reboot, run:

```sh
/jffs/hx-dns-load.sh
```

Then verify DNS resolution.

## current operational model

```text
/jffs/hx-hosts
    |
    v
/jffs/hx-dns-load.sh
    |
    v
/etc/hosts
    |
    v
dnsmasq on 192.168.50.1
    |
    v
hxs-N.hx.local.arpa -> server IP
```

This is the current approved local DNS workflow for HX infrastructure.
