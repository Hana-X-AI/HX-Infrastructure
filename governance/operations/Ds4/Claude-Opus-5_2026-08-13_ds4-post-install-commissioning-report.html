2The state machine

Thirteen gates, in the owner-specified order, deliberately not collapsed. A successful build is not proof of model fit, and a working HTTP endpoint is not proof that an agent client behaves correctly.

The driver stops at the first unmet gate, because a later gate cannot be meaningfully assessed before an earlier one. Current output blocks at INSTALLED and skips the remaining twelve with "not evaluated — earlier gate unmet".

3The capacity gate is bound to the artifact — and it is enforced

A PASS for one quantization is not a PASS for another

CAPACITY APPROVED is not "the gate passed once". The recorded verdict carries the model identity and quantization it was evaluated against. Change either, and the prior result goes stale and the gate reopens automatically.

Proven with a simulated workload:

selected artifact : ds4f / q2
recorded verdict  : PASS, evaluated for ds4f / q4
driver output     : BLOCKED  CAPACITY APPROVED
                    capacity gate result is STALE: it was evaluated for
                    'ds4f/q4' but the selected artifact is 'ds4f/q2'
                    - the gate must be rerun

This is mechanism, not discipline. It cannot be satisfied by remembering to rerun the gate.

Design choices worth flagging

  • Arbitrary GGUF support is not assumed. The DS4 source states plainly that arbitrary GGUFs are unsupported, so the schema requires confirmation that the installed revision supports the chosen model.
  • CLI flags are not hardcoded. The gate requires deriving them from the installed revision's --help, because flags in any plan may not match the installed build.
  • Loopback before network. The server profile defaults to 127.0.0.1 with network_exposed: false; exposure is a separate later gate.
  • The systemd unit represents the workload, never the host role, and carries no hard Requires= on remote units — it checks dependencies itself and retries.
  • Claude Code integration never overwrites the operator's provider config. An explicit launcher points at the DS4 endpoint; normal Claude Code is untouched.
  • The hook-denial commissioning step passes only if the hook denies, the model recognises the denial, recovers via the approved path, and does not fight the hook — not merely if the model never attempts it.

9Recommended next live action

Settle the RAM question before installing anything

The gate's System RAM row is the first thing worth resolving: hxs-3 has 66 GB, and the smallest DS4 variant documented in the reviewed snapshot targets 96/128 GB machines. Installing DS4 before choosing a model that fits — or choosing a different host — spends effort on a workload the evidence already says does not fit.

The productive order is: pick a supported model and quantization that fits 66 GB, populate model_selection, rerun the capacity gate against that exact artifact, and let the gate answer. If no supported variant fits, that is the answer, and it cost nothing to find out.

The vLLM/Qwen lane is unaffected and remains the primary target. Nothing here blocks it.
