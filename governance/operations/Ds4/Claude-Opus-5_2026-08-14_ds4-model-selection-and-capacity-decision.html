2Two execution modes, evaluated separately

The earlier gate collapsed everything into one verdict. It now evaluates each supported mode against the same artifact, because a model too large to hold resident may still run streamed.

MODE 1 — full residency / CUDA tensor-parallel: FAIL

~81 GB artifact against 32622 MiB (~31.9 GB) aggregate across 2 GPUs. Upstream states two cards do not have enough memory for these Flash models, and CUDA refuses to start if model layers would spill to the CPU. Tested Flash CUDA topologies are Q2 on four cards and Q4 on eight.

Not pursued.

MODE 2 — CUDA SSD streaming / single GPU: COMMISSIONING CANDIDATE

Streaming exists so the routed-expert portion need not stay resident. Mainline supports it on CUDA and QA covers it. What must still fit one 16 GB card is the non-streamed tensors plus KV plus graph scratch — and that is exactly what the live test will establish.

Single GPU is a hard runtime constraint, not a preference. Verified in source:

ds4: --ssd-streaming is not compatible with multi-GPU placement

GPU 0 runs DS4; GPU 1 stays reserved during commissioning. What to do with the second card is a separate decision after DS4 is operational on one.

3The 66 GB finding, corrected

Scoped, not fatal

The previous gate said 66 < 96 therefore FAIL. That was right for full residency and wrong as a verdict on the workload. The 96/128 GB figure describes the preferred environment for full-resident Q2; streaming exists precisely so the model need not be cached whole in RAM.

The gate now reports:

Host RAM is still never counted as CUDA device memory. The two are reported separately and an invariant now enforces that they are not conflated.

11Next action

Verify hxs-3 NVMe capacity and sustained performance

That is the only thing standing between here and a model download. It needs the fast NVMe filesystem that will host the GGUF identified, well over 100 GB free confirmed, and sustained read measured — because under streaming that device is in the decode path.

Once it passes, the sequence is: build current mainline DS4 CUDA, download ds4f-q2, then the one-GPU CLI run at 8 GB cache and 4096 context.

Expected throughput on this configuration is low — the published single-16 GB CUDA result was roughly sub-2 tok/s depending on caching mode. For the present goal, getting a real local model operational so HX hooks, skills, tools and agent behaviour can be tested against it, that is usable.
