What remains valid in both documents

The core architecture decision survives reconnaissance. OmniRoute remains the HX AI traffic plane, not the HX governance, infrastructure, memory, skill, or agent authority.
  • OmniRoute replaces the planned LiteLLM gateway role: still valid as a target-state architecture decision.
  • Narrow adoption: protocol gateway, approved provider routes, static routing first, traffic evidence, later resilience only after fidelity.
  • Authority boundary: SERVER-REGISTRY owns host truth; runtime profiles own approved workloads; HX acceptance owns behavioral proof.
  • Excluded product features: OmniRoute memory injection, embedded skills, A2A/agent orchestration, broad MCP mutation/control, MITM/root CA, keychain import, and cloud sync remain outside the initial HX traffic-plane role.
  • Direct-versus-routed acceptance: remains essential. A direct runtime pass does not prove the gateway route.
  • SSRF owner exception: remains an explicit owner decision and must stay conspicuous, bounded to the trusted network, and paired with authentication and least privilege.
  • No deployment by implication: both documents correctly require separate authorization before live installation or deployment.
