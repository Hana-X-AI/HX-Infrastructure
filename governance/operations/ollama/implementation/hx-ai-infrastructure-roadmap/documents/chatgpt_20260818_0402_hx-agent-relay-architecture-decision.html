Executive verdict: Adopt a GitHub-backed, locally executed HX Agent Relay. GitHub carries governed work orders and reviewable results. hxs-cp remains the execution authority. Google Drive remains a human collaboration and source-intake plane—not the agent command bus.

Target operating flow

1 · Owner intentChatGPT prepares a structured work order.
2 · Immutable taskThe relay snapshots and hashes the approved task.
3 · Local executionKimi or DeepSeek runs after the library gate.
4 · EvidenceReports return through a branch and Tessa validation.
hx-task start 42 --provider deepseek

The real problem

Clipboard transfer carries owner authority, scope, context, instructions, and evidence at the same time. Layered addenda can therefore create drift even when the model remains operational. The answer is not a better clipboard; it is a governed task identity with an immutable snapshot and retained output.

Current risk

  • Prompts can be reformatted or truncated.
  • Addenda can conflict with the mission.
  • Approval and execution blur together.
  • No exact task hash reaches Tessa.
  • Results must be manually carried back.

Required outcome

  • One authoritative task packet.
  • Provider-neutral execution.
  • Local library gate and individual receipt.
  • Automatic attempt and evidence capture.
  • Separate implementation and validation.

Why the shortcuts fail

Remote Control

Disabled when ANTHROPIC_BASE_URL points away from api.anthropic.com; incompatible with the Kimi and DeepSeek launchers.

Channels

Research preview, Anthropic authentication, and a new sender authority. No immutable task or report.

Drive as command bus

Mutable and separately authenticated. It bypasses source locks and local receipts unless imported first.

Self-hosted Actions

Repository-driven code would execute on the control plane. GitHub warns about persistent compromise risk.

Local control surface

Begin with bounded Bash in platform/_shared/bash/. The relay verifies owner state, snapshots and hashes the task, creates the attempt, requires the library receipt, selects the isolated provider launcher, captures structured output, and blocks unauthorized stage advancement.

hx-task inspect <issue>
hx-task plan <issue> --provider <kimi|deepseek>
hx-task start <issue> --provider <kimi|deepseek>
hx-task status <attempt-id>
hx-task validate <attempt-id> --provider <validator>

Use Claude Code hooks at session start, prompt submission, pre-tool use, subagent start, task completion, stop, failure, and session end. Hooks are defense in depth; the outer relay independently enforces the critical gates.

Phased adoption

Phase 0 · Finish the foundation

Do not interrupt the current bootstrap. Record this architecture as proposed only.

Phase 1 · File-based relay

Named task packets, Termius SFTP, one-line @file, and a read-only -p pilot.

Phase 2 · GitHub work orders

Issue form, least-privilege API identity, actor validation, immutable snapshot, and human-triggered start.

Phase 3 · Reports and Tessa

Enforced report completion, reviewed result branch, and separate non-mutating validation.

Phase 4 · ChatGPT console

Connect and permission-test GitHub; ChatGPT prepares work orders and reviews results while owner approval remains explicit.

Phase 5 · Optional SDK

Consider the Agent SDK only after the CLI relay proves a real asynchronous need.

Trust boundaries

  • Provider credentials stay in existing mode-0600 profiles outside Git.
  • The relay calls provider launchers but never parses credential files.
  • The SSH key carries Git; issue access gets separate least privilege.
  • Pilot with a repository-scoped token; target a GitHub App with one-hour installation tokens.
  • An hx:approved label never replaces an approved human actor.

Acceptance standard

Must prove

  • Unapproved tasks are rejected.
  • Edits cannot alter a running attempt.
  • Every agent has its own receipt.
  • Missing reports block completion.
  • Provider failure cannot become success.
  • Tessa cannot mutate implementation.

Must not introduce

  • Broad Drive access for models.
  • Provider keys in GitHub or logs.
  • Automatic execution on issue creation.
  • Self-hosted Actions on hxs-cp.
  • Automatic merge or stage authority.
  • A second source of truth.

Proposed standing decision

PROPOSED HX-SD-006 — Agent Work Exchange Standard
GitHub is the governed HX agent work-order and review exchange. hxs-cp is the local execution authority. Agents execute immutable, hashed task snapshots against the local governed library and return retained reports and evidence. External collaboration systems may supply approved source material but do not replace the repository library, execution gate, or owner authority.
