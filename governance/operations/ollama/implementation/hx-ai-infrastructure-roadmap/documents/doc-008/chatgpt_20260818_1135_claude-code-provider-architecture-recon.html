The constraint that determines the architecture

`ANTHROPIC_BASE_URL` is process-wide. A Claude Code process pointed at Kimi cannot send a native subagent to DeepSeek merely because an agent file names a DeepSeek model. That request still goes to the Kimi endpoint and fails or is misrouted. Separate processes work now; a future traffic plane can provide cross-provider routing after protocol acceptance.

REJECT

What is decided—and what is not

Decided

Kimi K3 is the default execution provider for Meta-Agent, Owen, Craig and Quincy. DeepSeek V4 Pro is Tessa's default independent-validation provider. DeepSeek V4 Flash is preferred for approved bounded-volume work. API keys remain external; mixed-provider native subagents are prohibited.

Still gated

Neither profile is configured or accepted. Traffic-plane cross-provider routing and any further named-agent reassignment remain separate governance decisions.

Recommended execution gate

When the CAIO says “configure,” give Claude the repository-native implementation prompt. The Kimi process performs read-only preflight, pauses for approval, implements both isolated profiles, completes its assigned tests, writes the retained handoff and stops. The owner or operator then starts `hx-claude --provider deepseek`; Tessa completes the independent gates and consolidated verdict. Configuration is not accepted until all twelve conditions pass.
