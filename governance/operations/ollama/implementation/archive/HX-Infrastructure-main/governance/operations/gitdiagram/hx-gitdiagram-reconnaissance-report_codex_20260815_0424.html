The decisive finding

STRONG

Fast orientation

Transforms a GitHub repository tree and README into an explanation, validated graph AST, Mermaid diagram, interactive source links, and PNG export. This is useful for onboarding and first-pass documentation.

EVIDENCE LIMIT

No source-code analysis

It does not read implementation files, parse ASTs, trace calls/imports/data flow, or inspect configuration bodies. Nodes and edges are inferred by an LLM from path names and README prose.

CURRENT BLOCK

Not HX-local by default

Ingestion is fixed to GitHub/default branch; AI is fixed to OpenAI or OpenRouter; persistence requires Cloudflare R2 and Upstash Redis. Local repositories and HX local inference are unsupported.

Engineering quality

STRONG

Defensive generation pipeline

The model emits a bounded Zod graph AST: maximum 10 groups, 34 nodes, and 48 edges. IDs, connectivity, and repository paths are validated; invalid structural output receives up to three attempts. Mermaid is deterministically compiled and comprehensively escaped.

STRONG

Browser rendering safety

Mermaid runs with antiscript security, configuration directives are stripped, only GitHub HTTPS click targets survive, generated SVG is sanitized with DOMPurify, and links are allowlisted again after rendering.

STRONG

Meaningful test surface

The snapshot contains 68 test files and approximately 531 test declarations, including API, storage concurrency, credentials, cancellation, quotas, Mermaid security, graph validation, and browser helpers. CI adds lint, typecheck, formatting, dead-code checks, dependency audit, build, performance budgets, and container build.

MIXED

Operational maturity

The application has deadlines, distributed locks, audit state, persistence rules, non-root container packaging, and health checks. Against that, it remains package version 0.1.0 with no releases or formal security policy, and its live architecture is tightly coupled to several SaaS services.

Security, privacy, and authority boundaries

Credentials are not merely “local”

User OpenAI keys and GitHub PATs are migrated from browser local storage into 30-day, HttpOnly, SameSite=Strict cookies scoped to /api. This improves script isolation, but the credentials are sent to and processed by the GitDiagram server on same-origin requests. HX must not interpret “stored in the browser” as “never reaches the server.”

Private data crosses multiple boundaries

A private repository’s path tree and README are sent to OpenAI or OpenRouter; generated explanation and graph artifacts are stored in Cloudflare R2. Private keys are namespaced by an HMAC of the caller PAT, which separates artifacts but also couples retrieval identity to token continuity.

No application identity plane

The project has credential possession and same-origin protections, not an HX user/group authorization model. Exposing it beyond loopback or a tightly controlled pilot enclave would require an external authentication/access layer.

Generated graphs can become false authority

Path validation proves that a linked path exists—not that the inferred component role, dependency, or data flow is correct. Every HX output must be labeled GENERATED DRAFT until reviewed against source and known ground truth.
