Agent Ariadne

A temporary, capability-first control-plane steward for the bounded LoopX pilot. Ariadne preserves the authoritative thread across sessions, executors, gates, failures, evidence, and quota—without becoming a second architect, task tracker, orchestrator, memory system, or adoption authority.

ARIADNE
Why this name: in the old story, Ariadne's thread made a complex path recoverable. That is exactly the pilot's question: can LoopX preserve the thread of intent, work-state, evidence, and the next safe move when an agent session disappears?

Executive decision

Create Ariadne as a new temporary specialist for the LoopX pilot. Do not expand Atlas, LangGraph, MCP-plane, or testing-qa into this role. Atlas evaluates code intelligence. LangGraph owns workflow graphs. MCP-plane owns tool admission. testing-qa rules on evidence. Ariadne owns one distinct pilot responsibility: the integrity of LoopX's execution-local work-state and transitions.

The key design choice

Ariadne is not the product-task executor. Combining ledger operator, work executor, validator, and adoption reviewer would make a LoopX demonstration easy and the evidence weak. Ariadne prepares the current bounded packet, a separate executor performs the slice, Ariadne validates real postconditions and operates writeback, and independent reviewers decide whether the run proves anything.
sdd-core intent→LoopX runtime state→Ariadne packet→bounded executor→real readback→Ariadne writeback→independent review→owner decision

Why the first pilot uses direct CLI

The LoopX reconnaissance found material defects in the Claude MCP adapter and an insufficient Bash boundary in the Claude hook. The first pilot therefore excludes both. Ariadne calls a pinned LoopX CLI directly, consumes JSON, and records typed identities, revisions, receipts, and exit status. This tests the kernel's real value without confusing adapter behavior with kernel behavior.

Host containment is enforced before invocation, not assumed. The pinned LoopX CLI runs under an isolated OS identity or container with explicit writable mounts limited to the pilot roots, disabled network egress, and a credential-free environment. A preflight record verifies each containment control — identity, writable-mount scope, network egress off, no credentials present — before execution; a failed containment check is a G2 hard stop.

Not permitted: one-line installer, user/global configuration, Claude adapter or hook, MCP, status server, HTTP, scheduler, heartbeat, peer launcher, reward memory, probes, dashboards, connectors, self-update, auto-repair, or unattended automation.

Direct-CLI contract

The contract is defined before activation. The LoopX release is pinned to v0.4.6 through an immutable artifact path and digest. Each operation has a stable JSON schema and an operation-specific exit status, anchored to the canonical tick actions: decision (step 1), claim/readback (step 2), writeback (step 6), quota (step 7), and handoff (step 8). Every required operation produces a machine-readable result retained as evidence.

What makes this agent pilot-ready

Operational contract

  • Complete activation charter with required pins, paths, budgets, executor, reviewer, and thresholds.
  • Exact authority hierarchy and no-dual-write rule.
  • Direct-CLI integration and machine-readable responses.
  • Eight-step tick protocol and typed result vocabulary.
  • Re-entry instruction that rejects chat memory as current state.

Evaluation contract

  • Nine gates, positive/negative controls, and crash injection at six transition points.
  • Blind handoff test and strong sdd-core baseline.
  • Privacy/containment tests and protected-path manifests.
  • Immutable hard-stop runs—no fixing forward.
  • Required evidence tree, gate schema, and narrow advisory dispositions.

Hard stops that matter most

  • Missing owner authorization, mutable/unpatched source, or incomplete charter.
  • Any canonical/user/global change, listener, network effect, or adapter/installer requirement.
  • A second todo/gate/quota truth or proposed bidirectional synchronization.
  • Gate bypass, stale revision acceptance, expired-claim completion, or unvalidated success.
  • Quota spent before accepted writeback, spent twice, or recovered by repeating the product effect.
  • Private material in public/tracked projection or recovery that depends on chat memory.
  • Ariadne, executor, and independent reviewer collapsing into one authority.

A hard-stop result is preserved as immutable evidence. A corrected run receives a new run ID and complete preflight.

Recommendation

Use Ariadne for the LoopX pilot and retire it afterward unless LoopX earns a ratified permanent role. The agent is intentionally stricter than LoopX's default onboarding because this pilot must answer whether the kernel deserves authority—not merely demonstrate that it runs. The remaining prerequisite is the owner-approved activation charter: exact greenfield task, source pin, paths, executor, budgets, baseline, thresholds, and independent reviewers.
