Code-Graph-RAG as the Future HX Code Intelligence Plane

Roadmap decision. Code-Graph-RAG is worth pursuing, but not as a replacement for LightRAG and not as the primary index for today's HX-Infrastructure repository. Its best role is a future Code Intelligence Plane for code-heavy HX modules and external repositories, exposed to Claude Code and jcode as a structural read/query service.

6. Important epistemic strength

GOOD DESIGN: Code-Graph-RAG distinguishes FOUND, NO_FLOW and UNKNOWN in data-flow reasoning rather than treating missing graph coverage as proof of absence.

This aligns well with HX's own evidence model: uncertainty is explicit rather than silently converted into a false PASS.

11. Pilot metrics

  • Accuracy against known manual-review answers.
  • Time-to-answer versus grep/manual source navigation.
  • Number of files/tokens an agent must inspect before reaching the correct conclusion.
  • False relationship rate.
  • UNKNOWN vs false-negative behavior.
  • Cross-language consistency.
  • Index time and incremental update time.
  • Memgraph resource footprint.
  • Agent usefulness from Claude Code and jcode.
  • Tool-policy safety.

12. Initial pilot configuration philosophy

  • Use exact source snapshot/commit/version and recorded hash.
  • Do not use floating main or latest package.
  • Memgraph first; no vector database initially.
  • No nested CGR agent.
  • No CGR file editing.
  • No destructive DB tools exposed to agent clients.
  • Index jcode and OmniRoute only.
  • Use direct structural queries first.
  • Keep external repo indexing isolated and apply language-specific safety settings for untrusted code.
  • For C# external repos, use Tree-sitter-only mode unless compiler execution is explicitly authorized.

13. Worktree/project identity policy

Because Code-Graph-RAG project identity includes the resolved repository path, separate Git worktrees become separate graph projects. HX should therefore index canonical worktrees deliberately and avoid blindly indexing temporary worktrees.

14. LightRAG remains

Explicit roadmap decision: Code-Graph-RAG does not replace LightRAG. 
LightRAG:
what HX knows

Code-Graph-RAG:

Both may eventually feed Claude Code and jcode, but they answer different classes of questions and should retain separate storage/indexing semantics.

15. Final roadmap position

PLACE ON ROADMAP.
Code-Graph-RAG is a strong future Code Intelligence Plane candidate.

DO NOT deploy as a core HX service yet.
First prove value on jcode and OmniRoute using known-answer structural benchmarks and a deterministic intelligence-only tool boundary.
