2. Decision 3 invalidated part of my own reasoning

The Store ruling — that HX does not use LangGraph's cross-thread Store, because Mem0 is the single durable memory authority — rested on three statements. The third was "HX does not run the LangGraph Server / Platform runtime." That was the statement making the other two true by construction rather than by discipline.

The packaged-server ruling makes it false. That runtime provisions a base store automatically.

The ruling itself still stands: one durable memory authority, and it is Mem0. What changes is its character — from a description of something that does not exist, into a policy that must be actively enforced against a runtime that supplies the thing. The enforcement points stop being confirmatory and become load-bearing:

  • Startup must actively disable or refuse a provisioned store, not merely assert none was constructed.
  • The negative database assertion — no store tables in the schema — becomes the primary detection mechanism rather than a belt-and-braces check.
  • VERIFICATION REQUIRED — whether the packaged runtime permits a store to be disabled at all. If it does not, that is an owner decision requiring mem0 agreement, not a design detail.

Marked, not rewritten. Guessing at packaged-runtime behaviour without a pinned release would repeat exactly the error the upstream-pinning gate exists to prevent.

Two further consequences recorded rather than resolved: the checkpointer section — including whether the three psycopg parameters remain caller-supplied and whether the four-table shape and dedicated schema survive — must be re-derived at the pinned release; and Redis may move from INDIRECT to required depending on what the packaged runtime uses it for.

One thing the ruling settles: the served interface. "Does LangGraph serve an interface at all" was VERIFICATION REQUIRED; the answer is now yes, so listen address, port and transport become required values rather than conditional ones.

3. An open mechanism question under decision 1

Not a challenge to the ruling — a gap inside it. OmniRoute is placed on hxs-8, and a process on hxs-8 cannot reach a loopback socket on hxs-4 any more than LangGraph on hxs-11 can.

So the ruling settles the policy — only OmniRoute may consume remotely — while the mechanism by which OmniRoute fronts a loopback-bound endpoint on a different host still needs defining and measuring. Candidates include co-locating a plane component on hxs-4, or an explicit forwarding path. That definition and its measurement are prerequisites to granting accepted-network-consumable.

Recorded in runtime-acceptance-decisions.md under the ruling. Not resolved here.

4. Method ratified

governance/policy/migration-method-decision.md records the legacy-mining workflow as the repository's standard — no longer a pilot — after two validations: Docling with one integration boundary, LangGraph with six. Future services run it directly, with the same gates and no pilot framing.

Two principles are folded into repository-migration-pattern.md, each earned rather than invented:

PrincipleStatementEarned by
P-A — gate construction A gate must specify how it verifies, not only the property it claims. A gate that cannot fail is worse than none: it ships confidence. iss-018 — the checkpointer gate named the right property and both obvious constructions passed while persistence was broken.
P-B — acceptance scope An acceptance states exactly what it authorizes and how that was verified, never more. Materially different scopes become distinct states. iss-017 — a loopback-only acceptance was later read as remote reachability.

P-B is applied in the same pass that earned it: Qwen3.5-9B / hxs-4 now holds accepted-local-runtime (granted) and accepted-network-consumable (not granted), with the rule stated that a local grant never implies remote consumability.

6. What remains before acceptance

  1. Re-derive the Store, Redis and checkpointer sections against the packaged-server ruling, at a pinned release. This is the direct consequence of decision 3 and cannot be done from guesswork.
  2. Pin upstream — still an open acceptance-gate failure, recorded rather than concealed. Nothing in point 1 can be answered without it.
  3. Write the MCP-plane capability contract, confirmed mandatory by decision 4.
  4. Define and measure the OmniRoute-to-hxs-4 mechanism before accepted-network-consumable can be granted.
  5. Re-run all four capability reviews in separate contexts. No author self-certification.

Only then does the status advance from REVISED / NOT ACCEPTED to ACCEPTED FOR IMPLEMENTATION. Deployment on hxs-11 stays NO-GO until it does.
