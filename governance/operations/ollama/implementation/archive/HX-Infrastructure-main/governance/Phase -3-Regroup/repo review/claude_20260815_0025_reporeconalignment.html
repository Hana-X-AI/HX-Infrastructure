03The method spine — what makes this repo unusually disciplined

The project's real asset is not the fleet; it is a ratified method for turning legacy material and vendor docs into trustworthy target-state records. Two principles, both earned by a specific failure, now govern all future work (governance/policy/repository-migration-pattern.md, ratified 2026-08-14):

P-A · gate construction

A validation gate must specify how it verifies, not only the property it claims. "A gate that names the right property but cannot fail is worse than none — it ships confidence." Earned by iss-018 (a Postgres-checkpointer gate that passed via config-echo while persistence was broken).

P-B · acceptance scope

An acceptance states exactly what it authorizes and how it was verified — never more. Materially different scopes become distinct acceptance states. Earned by iss-017 (a loopback-only endpoint later read as network-reachable, same repo, same day).

Legacy migration is a ledger, not a merge. The 2025 archive is mined file-by-file through a frozen ledger — manifestv3.1resolved.jsonl, 522 rows, sha256 64eb356f…cd59, each row pinned to legacy commit a98846d6 — plus a provenance index. Dispositions are counted per row, never by pattern (a loose regex once inflated a coverage figure by five rows). Ratified as the standard workflow after two validations: Docling (1 integration boundary — accepted) and LangGraph (6 boundaries — method validated, design correctly failed). Corollary, load-bearing: a service's method pass is independent of its design acceptance.

The AI-runtime layer adds a parallel discipline: three evidence classes that are never substituted — A (protocol/client conformance, provable offline), B (model behaviour), C (performance/resource). "An offline fixture result is class A only. It is never evidence for B or C." A skip is not a pass (governance/policy/ai-runtime-acceptance-contract.md).

04The AI runtime reality

One runtime is commissioned: Qwen3.5-9B q4_K_M via Ollama 0.32.9 on hxs-4, isolated to the 8 GB RTX 5060. The measurements are unusually honest and carry three hard constraints every downstream client must respect.

The dangerous finding · iss-015

Prompt overflow is silently truncated, not refused. Above ~64,880 tokens the runtime discards the excess and processes only 32,770 — no error, no warning — then "answers confidently from the remainder." A wrong answer indistinguishable from a right one. No Ollama setting converts this into an error; the mitigation is client-side prompt bounding. This is the concrete reason the contract prefers vLLM (which errors on overflow) as the declared primary runtime — even though Ollama is what's actually running.

Two more constraints travel with the workload: GPU isolation on this host requires OLLAMA_VULKAN=0 + GGML_VK_VISIBLE_DEVICES=999 + CUDA_VISIBLE_DEVICES by UUID — CUDA-only isolation silently fails as the Vulkan backend re-enumerates both cards (iss-013); and overcommitting the card wedges the NVIDIA kernel context into an unkillable D-state requiring reboot, so a model must be unloaded before changing context size (iss-014, incident hxs4-wedge-001).

06The fault lines — cross-workstream contradictions & drift

These are the tensions that only appear when documents are read against each other. They are the substance of the regroup. Every one is live.

FL-1 · the flagship — iss-017

The only accepted inference capability is unreachable from the host meant to consume it. Qwen3.5-9B is accepted loopback-only on hxs-4; LangGraph (the named client) sits on hxs-11 and routes through the gateway on hxs-8 — neither can reach a loopback socket on hxs-4. Remote use is authorized only through OmniRoute, but OmniRoute on hxs-8 can't reach that loopback either. The policy is ruled; the mechanism is undefined and unmeasured. This is the top downstream blocker.

FL-2 · hxs-4 authority conflict — unruled

SERVER-REGISTRY.md (the declared source of truth) assigns hxs-4 Qwen2.5-3B + a Qdrant/embedding/rerank plane. The runtime-acceptance record commissions Qwen3.5-9B on the same 8 GB card — and act-014 confirms the registry-assigned workloads are not installed. Two authorities disagree about one host, and session-resume.md still marks it "unruled." Someone must rule which authority governs.

FL-3 · LiteLLM vs OmniRoute — registry is behind

Target state moved the gateway to OmniRoute; the registry still names LiteLLM on hxs-8 and hxs-9, and OmniRoute appears nowhere in it. Worse, the three authorities disagree three ways: registry says LiteLLM, LangGraph's design says "OmniRoute supersedes it / plane BLOCKED", and Docling's design still calls it "LiteLLM — legacy candidate." The entire network-consumable path rests on a component the registry doesn't list and that doesn't yet exist.

FL-4 · declared-primary runtime ≠ running runtime

The runtime contract names vLLM/Qwen as PRIMARY, and an invariant test enforces that label — yet the only operational runtime is Ollama, whose silent-truncation behaviour (iss-015) is exactly the failure mode vLLM was preferred to avoid. Not a policy violation (the contract is explicitly target-state), but a standing tension: the deployed path is not the declared one, and forward analysis notes Qwen3.5-9B under vLLM does not fit the 8 GB card at all — it belongs on the idle 16 GB card.

Drift worth an owner glance: several version pins anchor everything and will rot — Ollama 0.32.9, Claude Code 2.1.221 + its 28,440-token baseline, nvidia-driver-580 / CUDA 13.0. And the Qwen family naming is internally inconsistent across authorities: "Qwen 3.8 27B" (hxs-1), "Qwen2.5-3B" (hxs-4 registry) vs "Qwen3.5-9B" (hxs-4 acceptance), "Qwen2.5-Coder-32B" (hxs-2). "Qwen3.5" is not a publicly released family as of the May-2025 knowledge cutoff — worth an owner confirm on the exact model identities.

08Open owner decisions — the queue

What actually needs a human ruling to move forward, highest-leverage first. None of these can be resolved by an agent — they are exactly the decisions the method reserves to the owner.

  • Rule the hxs-4 authority conflict (FL-2): does the registry (Qwen2.5-3B + retrieval plane) or the acceptance record (Qwen3.5-9B) govern that host? Everything about hxs-4's role hangs on this.
  • Define the OmniRoute reachability mechanism (FL-1 / iss-017): co-locate a plane component on hxs-4, or an explicit forwarding path — then measure it. Prerequisite to any remote Qwen use and to LangGraph having a model endpoint at all.
  • Reconcile the registry to target state (FL-3): add OmniRoute, retire the LiteLLM cells — or explicitly rule the registry stays as-built until Phase 3 touches each host.
  • Schedule (or shelve) LangGraph implementation: the iss-019 backlog is the correction list; the packaged-server mode is final and not to be re-litigated.
  • Green-light the approved pilots: OmniRoute, jcode, and Code-Graph-RAG are all approved-to-pilot but none has begun — each needs a go and a sync checkpoint.
  • Authorize Phase 3: server implementation is READY but requires its own authorization.

09The lessons-learned through-line

Thirty-three recorded lessons (governance/logs/lessons-learned.md) reduce to one sentence, and it is the right compass heading for the next phase:

"Parses" is not "passes" is not "proven" — and every claim rots or lies unless it is tested against reality.

The concrete forms it has already taken here: a syntax check is not an execution test (ll-001); an untested guard pattern is an unguarded path (ll-002, the RAID rule that could never match); a PCI BAR is an address aperture, not VRAM (ll-011); a hostname is a claim, not an identity (ll-026); a comparative claim is only true of the set that existed when it was written — closing one gap surfaced 27 stale superlatives (ll-030); a proposal complete enough to act on will be read as a decision (ll-032); and a document that warns about a secret will happily print it (ll-033). The defects in §7 are new instances of the same lesson — which is why the recon that finds them matters.

What this document is. An alignment record produced by reading the full repository against its own authority order and hunting for contradictions. It asserts no as-built change and assigns no roles. Every claim traces to a file, an ID, or an issue row; where sources disagree, both are named. Prepared for the HX-Infrastructure regroup phase.
