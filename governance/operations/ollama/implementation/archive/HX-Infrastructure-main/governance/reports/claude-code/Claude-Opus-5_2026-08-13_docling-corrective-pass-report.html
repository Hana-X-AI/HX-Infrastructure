Three corrections to what was handed to me

It is v3.0.0, not v2.x. The assessment said the change came "since v2.0". Current is 3.0.0.

There are two conversion modes, not three. ConversionMode holds exactly remote (default) and local. "Hybrid" is not a mode — it is fallback_to_local, a boolean defaulting to false. Upstream's own README calls it a mode; the source does not.

It is no longer FastMCP. v3.0.0 moved to MCP Python SDK v2 — mcp[cli]>=2.0.0,<3.0.0, from mcp.server.mcpserver import MCPServer. My own first-pass document said "a FastMCP server". That was wrong and is corrected. It also sharpens the hxs-7 question: that host's assigned workload is literally "FastMCP runtime", and this is no longer a FastMCP server.

Also verified and patched in: requires-python >=3.10 with classifiers through 3.14; six toolgroups with three loaded by default; real base dependency names; and the settings defaults. All optional RAG and information-extraction toolgroups are disabled by HX default — and two of the three write to a vector store, not one as previously stated.
