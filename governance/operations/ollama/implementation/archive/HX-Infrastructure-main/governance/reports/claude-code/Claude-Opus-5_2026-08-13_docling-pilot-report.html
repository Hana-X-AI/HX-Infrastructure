5The single most shaping current fact

hxs-12 has no GPU

Docling's assigned host carries an Intel HD Graphics 630 integrated adapter and nothing else. No NVIDIA, AMD, NPU or other accelerator; no CUDA or driver package installed. It has 4 cores with no hyper-threading, 32 GB of non-ECC memory, and a single 238.5 GB disk with no second device and no spare capacity.

Everything in the design touching OCR, vision models or throughput follows from this. The pipeline's accelerator setting resolves to CPU. Vision-model features are available but are not enabled by default. No model-serving runtime becomes a Docling dependency, and no GPU toolchain pinning appears anywhere in the document.

9Findings worth your attention

The tool surface was never settled

Three mutually incompatible inventories exist: the node README lists 21 tool names, the upstream package ships 19 different ones, and the HX specification defines a third set of 19. The 2025 functional tests were written against the README naming — so they did not test the tools the package actually ships. Only the upstream inventory was established by reading the package source. This is flagged as the least safe part of the inherited design to copy forward.

The implementation drifted back to a design decision that had been reversed

The 2025 gap analysis recorded a critical conflict — Docling was not to install LightRAG locally — and a collection-ownership conflict with the separate LightRAG service. Both were corrected. Yet the task breakdown still contains a direct vector-store client, collection initialisation, entity and relationship insertion, payload indexes and vector search. The correction was made in the design and lost in the build. That is precisely why Qdrant is classified INDIRECT rather than inherited as a direct contract.

Two safety defects worth remembering

A redaction pattern for bearer tokens had no capture group for the bearer form, so the substitution failed and the token was not redacted at all — a redactor that silently did nothing. Separately, the model cache failed with permission denied because the service unit's sandboxing hid the very directory the default cache path pointed at. Both are carried as constraints, neither as a hardening proposal.

10Deviations declared

No approved secret scanner exists in this repository

.claude/hooks/ contains no guard, and the password guard named in iss-012 is gone. The two known values are also, correctly, recorded nowhere — so they could not be supplied to a scanner even ephemerally.

Substituted control, which is structurally stronger than scanning after the fact: the document is authored from extracted meaning, never copied text, so no literal from a secret-bearing row can reach it. That is backed by a pattern scan of the output covering assignment forms, key prefixes, bearer literals, JWT shapes, private-key blocks, vault markers and high-entropy strings. All returned zero.

One tool fetch was auto-persisted by the harness

A single batched fetch of the charter files exceeded the inline output limit and the harness wrote it to its own session results directory. That is outside this repository and outside git objects, but it is a copy of legacy text on disk that I did not intend to create, so it is recorded here rather than left unmentioned. Every later fetch was reduced in-shell to stay under the limit.
