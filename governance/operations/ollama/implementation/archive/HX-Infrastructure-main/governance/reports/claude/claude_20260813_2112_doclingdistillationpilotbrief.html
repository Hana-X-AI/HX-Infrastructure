Hard boundaries — read first

Planning / migration only. No infrastructure implementation, no server configuration, no deployment, no package installs on any host. This pilot produces documents and ledger updates, nothing else.

Freeze v3. Do not re-review or re-open the manifest architecture. v3 is the migration baseline; the repository architecture is settled. If you believe a ledger row is mis-dispositioned, note it in the return package — do not re-classify the manifest.

Secret-clean. No historical credential value and no secret-bearing raw content may appear in service.md or any output. Provenance references (ledger IDs) are sufficient. Never open the excluded/retired vault rows for content (see §2).

No shadow archive. The 198 historical files stay reachable only through the sanitized legacy lineage. None of them may be copied under current main.

5Verification-required discipline

Every current-fact claim carries a state: verified against 2026 authority (cite the authority) or VERIFICATION REQUIRED. Never let a 2025 value pass silently as current. Apply especially to:

  • package/library versions and the Blackwell toolchain pins;
  • ports, host/IP assignments, FQDNs (reconcile to 192.168.50.x / hx.local.arpa / hxs-N);
  • MCP/API surfaces and command invocations;
  • model endpoints (serving stack details are VERIFICATION REQUIRED — do not assert a vLLM-fronted or any other specific serving configuration unless a direct 2026 project authority from discovery records or SERVER-REGISTRY.md is cited; workload and model choices come from project records only);
  • system requirements (GPU/VRAM, storage, cache paths).

7Ledger closure — what to write back

Update the Docling rows in manifest.jsonl (and emit provenance-index.jsonl entries) so each row records its outcome. Do not alter dispositions or the schema — advance state and fill provenance.

  • migration_status: advance rows actually distilled from pending → migrated; leave untouched rows pending with a reason.
  • distilled_into: the service.md section(s) each row fed (mirror in provenance-index).
  • reviewed_by: the SME(s) who signed the section it fed.
  • sanitized_sha256: fill where the sanitized source hash is known; else leave null with a note.
  • migration_commit: leave null (planning only) — this is filled at real execution.
  • Rows that remain purely historical stay sanitized-ref; confirm none flipped to a main target.
