The lean principles this merge follows (post-pivot — no phase gate):

  1. Registry stays the source of truth. SERVER-REGISTRY.md owns hosts, hardware and committed roles; the v0.3 architecture is the proposal the owner draws from. Merged build material aligns to that proposal but does not overwrite the registry.
  2. Discovery is immutable. servers/<host>/discovery.md is as-found and never rewritten; build/config state lives separately.
  3. Lean, not heavy. Adopt the legacy ideas and assets, not its ceremony. No competing process docs; prefer existing files; one lean doc per service, not a 90-file task tree.
  4. Lean on the agents. Bring the SME agent roster across and let it do the build work — that is the biggest time-saver in the legacy repo.
  5. No secrets, ever. The Ansible vault never enters tracked docs.

│  ├─ docling-mcp/build.md       (→ aligns to the v0.3 Docling host)

Rationale: services/<name>/build.md is the whole footprint of the legacy nodes/<node>/ tree collapsed into one lean doc — install, config, integration, validation, and gotchas — because the agents supply the discipline the 90-file task trees used to encode. Each service doc names its owning agent and the host it maps to under the v0.3 proposal, so build work is traceable without a heavyweight process.
