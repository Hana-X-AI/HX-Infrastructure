2The genuinely new finding — verified, not relayed

Current Docling MCP upstream has moved to remote/local/hybrid — the design's "embedded, unchanged" is stale NEW · VERIFIED

GPT flagged that the pilot's service.md describes Docling running "embedded, in-process… unchanged in shape from 2025," and that current upstream no longer works that way. I checked the current docling-project/docling-mcp sources directly rather than take it on trust. Confirmed: since v2.0 the package ships three conversion modes — remote (the recommended default, which calls a Docling Serve API), local (docling-mcp[local]), and hybrid (local fallback) — and advertises "no model downloads required for default remote mode." It also exposes optional RAG toolgroups including Milvus upload/retrieval, and supports toolgroup selection at launch.

This isn't the pilot's mistake — it faithfully distilled the 2025 material, which predates this change. It's exactly the failure mode the "reconcile against current authority" rule exists to catch, and the one thing neither the pilot nor my v1 assessment checked: current upstream itself. The consequence is real — if HX runs remote mode, then native libraries, model weights, OCR artifacts and cache directories belong to Docling Serve, not to the lightweight MCP façade, which rewrites several sections of the document.

4Provenance — accountable, not yet reproducible

GPT's independent parse matches the pilot's: 198 records, 198 unique IDs, all 120 used rows carry a distilled_into target, all 3 blocked rows have read_from=null, every sanitized_sha256 and every reviewed_by empty. Internally consistent — good accounting. The gap is forensic: a future agent can say "this came from lgc-127" but cannot prove which exact version of lgc-127 was read, because the record carries no source path / commit / hash.

Fix: either add source identity to each provenance record, or bind the whole index to a manifest_sha256 and require the ledger to hold exact source identity. The minimal record becomes:

manifest_sha256 · legacy_path · source_repo · source_ref · source_commit ·
source_sha256 · sanitized_ref · sanitized_sha256 · distillation_status ·
distilled_into · reviewed_by · migration_commit

7What must NOT be reopened

The pilot found implementation defects in the machinery; it did not invalidate the merge architecture. These are settled — don't relitigate them in the corrective pass.

  • One canonical repo, one active current truth, registry authority.
  • No shadow legacy tree in active main; capability-first specialist model.
  • Historical defects distilled into current constraints; target-state docs separate from as-built.
  • Model-serving separated from core document parsing; detailed MCP hardening deferred.

Bottom line

The pilot did exactly what a pilot is for: it proved the valuable part of the method on real material, and it exposed four fixable faults in the substrate before we multiplied them across LangGraph's 213 files. Do not redo Docling — the content work is good. Fix the substrate once (v3.1 ledger, real sanitized lineage, current-upstream patch, provenance identity, four SME contracts), re-run acceptance clean, commit, then LangGraph reuses a genuinely proven process instead of an almost-proven one.
