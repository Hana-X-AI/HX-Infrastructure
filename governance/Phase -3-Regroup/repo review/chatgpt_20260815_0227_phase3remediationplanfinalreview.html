Recommended sequence

  1. Wave 0 — establish evidence: authoritative checkout, exact Git state, exact source hashes, protected remediation branch, clean baseline, and preserved test outputs.
  2. Wave 1 — close the live safety gap atomically: lifecycle truth repair plus fail-closed guard repair. Merge only when both are green together.
  3. Wave 2 — repair deterministic defects: runtime contract, installer idempotency, tracker generator/parity, LangGraph status, canonical test path, and risk review preparation.
  4. Wave 3 — reconcile records: hxs-4 intended role vs observed runtime, current authority labels, expired risks, external-asset notes, and versioned current baselines.
  5. Wave 4 — architecture decision preparation: full-stack recon synthesis, true-north principles, OmniRoute alternatives, deployment-order dependencies, decision criteria, and non-mutating test plans.
  6. Close Phase 3: owner approves the reconciled truth baseline and the decision roadmap. A separate future authorization determines whether/when implementation begins and what that phase is called.

Minimum corrected acceptance gates

  1. The final joint brief filename and full SHA-256 match the supplied artifact.
  2. No current authority document claims Phase 2 is server configuration or Phase 3 is server implementation; historical records remain intact and clearly labeled.
  3. During Phase 3, protected mutation commands deny by default for READY, COMPLETE, missing, malformed, duplicate, and unrecognized authorization states.
  4. No acceptance test invokes a live server, remote endpoint, package manager, service manager, storage command, network reconfiguration, or operational commissioning path.
  5. The installer produces structurally identical hook configuration after one and two runs, with exactly the packaged set of seven hook commands.
  6. Runtime contract recovery is traceable to a known-good Git object or separately evidenced reconstruction; semantic required fields pass.
  7. Markdown and generated HTML tracker ID sets are equal and unique without hard-coded totals.
  8. All 15 discovery records and the resolved ledger match the verified baseline objects, not just the current working tree.
  9. OmniRoute artifacts remain proposed/parked until full-stack architecture, deployment order, and owner authorization are complete; no network-consumable grant is issued in Phase 3.
  10. Phase 3 closure authorizes only the next approved decision or planning activity unless the owner separately and explicitly authorizes implementation.

Final assessment

Keep the plan; correct its authority edges. Claude did the hard part well: it transformed reconnaissance into testable work. The remaining weaknesses are concentrated where plans become policy—phase numbering, mutation authorization, architecture selection, and execution gates. Once R-01 through R-05 are incorporated, this becomes a strong Phase 3 remediation plan suitable for controlled execution on an authoritative checkout.
