The script is careful work: $PSScriptRoot rather than $PWD; root containment checked on the resolved path so symlink and junction escapes are caught; fail-closed on both zero and mismatched counts; same-directory temporary file so File.Replace is genuinely atomic; byte-for-byte validation before replacement; validated temp preserved on failure; per-path cleanup that warns rather than throws and continues after a first failure. Two suspicions I raised and withdrew

Recorded so the negative work is visible and not repeated.

HypothesisOutcome
The ledger permits one authority to sign all six approvals — the M-02 self-certification analogueREFUTED — line 118: "The four authority identities must be pairwise distinct. None may be Ariadne, the LoopX executor…"
Approval receipts lack key expiry and revocation checksREFUTED — the trust registry must "provide the Ed25519 public key and validity interval, and show that the key is not revoked at verification time." My keyword scan missed the vocabulary

The cryptographic construction is sound, and two choices are better than typical: hash-equality is checked before signature verification, and the signing string is domain-separated as HX-LEARNING-PROMOTION-APPROVAL-V1\n<receipt_sha256>\n, which blocks cross-protocol signature reuse. Replay is bound by candidate, destination-change, record and trust-registry digests rather than by a time window — stronger here than a max-age bound, so its absence is a design choice rather than a gap.

3 · One control gap that closes on this transition

Throughout this session I have flagged that writes through the cloud device bridge bypass the hooks entirely — they are filesystem writes, not Claude Code tool calls, so no PreToolUse gate evaluates them. That is proposed as an iss- row.

Moving to a Claude Code session at the repository root closes that gap for all work done in that session. The authority-edit guard, the permanent-policy guard and the mutation guard all fire on tool calls there. It is a genuine control improvement, and it is the strongest argument for the transition beyond convenience — provided the checkout carries the hard-locked guard, which is precisely why the cherry-pick comes first.
