The three-stage lifecycle (resolves H2)

1 · Phase 3 — Regroup

Planning, decisions, and control-correction that only tightens (the guard hard-locks). No server contact. No control is loosened. Closes at C-02 once Gate A passes. Deliverables include P-F1's design spec as a document — no executable parser.

2 · Transition Stage

Separate and owner-authorized, opened by Gate B. Here the executable authorization parser (P-F1) is built and validated, the hard lock is deliberately replaced, OmniRoute topology is selected and measured, and implementation is planned. Still governed; the first place a mutation release can exist.

3 · Server Implementation Phase

Number TBD (owner ruling P-D0). Actual server configuration. Requires its own separate, explicit owner authorization — never implied by closing Phase 3 or by Gate B.
