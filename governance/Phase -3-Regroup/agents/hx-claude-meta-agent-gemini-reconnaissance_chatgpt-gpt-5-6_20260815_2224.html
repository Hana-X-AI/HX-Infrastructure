Claude Meta-Agent: Gemini Input Review

Verification of the proposed delegation, spawning, guardrail, error-handling and state-registry patterns against current official Claude Code and Claude Agent SDK behavior and the owner-approved HX three-tier architecture.

Prepared 15 August 2026 · Official documentation statically reviewed; no Claude Code configuration changed

Disposition: ADOPT THE PRINCIPLES WITH CORRECTIONS.
Gemini’s high-level instincts are good: isolate context, delegate atomic work, cap fan-out, normalize results, escalate repeated failure and retain minimal state. But its proposed spawn_sub_agent interface is not Claude Code’s native mechanism; the token budget is not a native per-agent control; its retry rule is too broad; and unrestricted specialist spawning conflicts with the owner-approved rule that Max is the sole dispatcher and Tier-3 task agents are non-recursive.
KEEP

Architectural intent

Claude handles owner intent and systemic routing; specialists remain domain-bounded; task contexts stay small.

CORRECT

Native mechanism

Use Claude Code’s Agent tool, agent definitions, hooks, tool restrictions, maxTurns, isolation and runtime limits—not an assumed custom schema.

REJECT

Recursive autonomy

Do not let every specialist spawn freely. HX retains Max as sole dispatcher and removes Agent from Tier-3 tools.

VERIFY

Runtime topology

Prove whether Max runs as a first-layer subagent, dedicated main-session agent, or another governed handoff before writing final controls.

Recommended HX delegation topology

Keep the approved model unchanged: Claude owns intent and owner authority. Max owns dispatch and integration. Stewards own domain knowledge and review. Tier-3 task agents perform atomic work and cannot spawn.
Agent Zero
   ↓
Claude — Meta-Agent, intent and synchronization
   ↓
Max — sole dispatcher and integrator
   ├─ persistent stewards — advise, scope, review
   └─ Tier-3 task agents — execute atomic responsibilities; no Agent tool

Enforcement, not merely prompting

  • Give Agent only to the approved coordinating layer.
  • Remove Agent from Sam, Ruth, Will, Brooke, Paul and Sue through tools or disallowedTools.
  • Set the depth to the chosen topology; do not rely on the product default of three.
  • Use a conservative concurrency cap during the pilot.
  • Set maxTurns per task-agent type.
  • If using the Agent SDK, cap the whole query’s spend and treat it as a circuit breaker, not a planning budget.
  • Use PreToolUse/SubagentStart hooks to block unauthorized spawning and mutating tools.
  • Require a Knowledge Base Review receipt before the first task tool. Custom subagents load CLAUDE.md, but they do not inherit files the parent already read.
Important implementation gap: native Agent(agent_type) allow-list syntax is documented for an agent running as the main thread with claude --agent. Inside a subagent definition, listing Agent permits spawning while a parenthesized type list is ignored. Therefore, if Max runs as a subagent beneath Claude, exact child-type enforcement needs scope control, permissions and/or a deterministic hook—not Max’s prompt alone.

Corrected result and failure envelope

Use governance/schemas/agent-result-envelope.schema.json, version hx-agent-result/v1, to wrap the native Agent result rather than pretending this is Claude Code’s tool schema. It is the sole contract for observed read/write scope, validation commands and results, independent review, and the classified error object. Producers and validators must consume that schema instead of maintaining an inline variant.

Retry policy

  • At most one automatic retry: transient API interruption, deterministic formatting failure or narrowly correctable syntax error.
  • No automatic retry: knowledge review incomplete, permission denied, security stop, unauthorized scope, missing owner decision, worktree collision, evidence-integrity failure or concurrency limit that explicitly says not to retry.
  • Every retry receives a new run identity and preserves the original failure evidence.
  • After the permitted retry fails, Max stops and reports the exact task, module, native error, evidence references, retry history and hypothesis to Claude.

Corrected state-registry pattern

Gemini is right that Max should retain transitions rather than raw conversations. The durable form should be a task-scoped evidence registry, not an ungoverned internal memory or second project tracker.

Registry retainsRegistry does not become
Task/run IDs, agent identity, source identities, status transition, input references, output/evidence references, validation result, retry count, reviewer, next authority and timestamps.Owner decision log, architecture truth, canonical actions/issues log, source repository, Mem0 memory, LoopX ledger, LangGraph checkpoint store or substitute for raw evidence.
  • Reference large inputs and outputs by governed path and hash; do not paste them into Max’s active prompt.
  • Retain raw evidence according to policy; compact only the active working context.
  • Update transitions atomically and preserve failed attempts.
  • Resume from the last independently verified state, not the last agent claim.
  • Never pass a prior agent’s full response to the next agent when a smaller evidence-bearing payload is sufficient.

Recommended changes to the Meta-Agent draft

Do not replace the current draft. Add a delegation-control appendix after the runtime pattern is selected. The appendix should include:

  1. Native Agent terminology and version requirement.
  2. The exact Max runtime pattern and approved depth.
  3. Agent tool allow/deny rules and hook enforcement.
  4. Per-agent maxTurns, model/effort and concurrency policy.
  5. Optional whole-query SDK spend cap.
  6. The HX result/failure envelope.
  7. The task-scoped state registry and retention boundary.
  8. The classified one-retry policy.
  9. Explicit deferral of experimental agent teams and a custom spawning service.

Final recommendation

ADOPT WITH CORRECTIONS.
Use Gemini’s delegation, context-minimization, structured reporting, failure escalation and state-compaction ideas. Implement them with Claude Code’s native Agent architecture and deterministic HX controls. Preserve Max as sole dispatcher. Keep Tier-3 non-recursive. Do not build a custom spawning tool, promise a per-agent token cap, use the three-step heuristic, or rely on prompt-only enforcement.

Next synchronization decision

Before updating the canonical Meta-Agent definition, select one runtime pattern for a bounded control pilot:

  1. Claude main → Max subagent → Tier-3, with hook-enforced spawn policy; or
  2. dedicated Max main session with native child allow-list and a governed Claude↔Max handoff.

The pilot should prove: only Max can spawn; Tier-3 cannot; knowledge-review receipts block tools; depth/concurrency/turn/spend limits work; error classification and one-retry behavior are correct; worktree isolation holds; and the state registry resumes from verified evidence.
